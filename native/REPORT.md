## What changed
- **The scan is gone from the default path.** Classic Cloud 3D went over all dots 72 times (3 depth bands × 24 colours) and Cloud 2D 24 times. Now each dot carries its colour *index* (the wheel bin 0–23, or 0/1 for Sign) and the vertex shader picks the colour (`render/shaders.h`, `kBlobVS`, new blob kinds 5 and 6). One `blobsPalette` call, as before. Applies to every place dots were coloured: Classic 3D, Classic 2D, Slice, and Glow (soft dots) in all of them.
- **Same picture:** the old order (band by band, group by group, dot order) is kept by a counting sort (two passes), because the dots are alpha-blended and the order changes pixels. Bands, bin boundaries and colours are the same code as 0.12.
- **One place for the mapping:** `phaseRgb` / `phaseBin` in `phase_wheel.h` is the reference; the GLSL `phaseRgb` is a direct port (comment points to it; 32-bit floats instead of doubles). New code: `src/atom/cloud_dots.*`; all GLSL moved unchanged into `src/render/shaders.h` (the other 9 shaders are byte-identical).
- **Decision (DECISIONS.md):** the dot carries the colour *index*, worked out on the CPU by `phaseBin` as before, not the raw phase: a 32-bit phase on the GPU could land in the neighbouring bin within ~1e-7 of an edge, and jumps/superpositions compute their index on the CPU anyway. So that one pass over the dots is still on the CPU.
- **Old path kept:** `AtomLab::gpuColours` (default On, not saved), checkbox "GPU colours (Atom Lab cloud dots)" in the Performance card (Atom Lab only). Off = the 0.12 scan. Small honest difference: the old scan now first builds an index list and then the blobs (v0.12 pushed blobs inside the loops), a few microseconds of extra work for the baseline.
- **Benchmark:** scenes 8–22 keep numbers, names and settings; 8 and 10 run with GPU colours On (set explicitly), new **23** = scene 8 and **24** = scene 10 with Off (same dots, tested). The run text says "GPU colours On/Off". Descriptions of 8, 9, 10 say what changed and that the speed-up is expected.
- **Text bugs fixed:** scene 19 said "compare with scene 8" → **scene 2** (checked: scene 2 is the Atom Lab Orbit view of U-238, scene 8 is the Wheel cloud; the text's own "Orbit view" meaning fits scene 2; I did not measure which is the better baseline). Scene 22 said "scenes 16 to 18" → **19 to 21**. Also found: the tick box said "11 extra" scenes (now counted: 15); README said "11 more, numbered 8 to 18"; three code comments mixed the internal index with the shown number ("scene 19 draws it" is shown 22, "same cloud as scene 2" is shown 3). All fixed. Every other scene cross-reference was checked by a test (all within 1–24, specific ones asserted).
